# 当前模型合同

参考模型的生成器、物理执行与必需比较算子整理在runtime/，保留函数的执行语义。当前上传扩展使用固定份额FIFO。它提供明确的资源与时间合同，参数用于合成机制检验。

## 资源、信息和单位

- 车辆旅行与采集非抢占；已启动操作锁定，未启动队列可以改派。位置用固定10×10网格的曼哈顿距离，服务、旅行、上传和处理时间均以分钟计。
- 一条归一化上行链路划分为N份TDMA。每车每周期拥有h=0.025分钟，周期T=Nh；车辆i的窗口为[kT+ih,kT+(i+1)h]，活动速率B=1。空份额不借用。
- 车内报文按采集完成顺序FIFO上传，跨窗口暂停/续传。采集可与本车上传并行。已承诺包即使过期仍排空，业务过期不免费释放物理承诺。
- 共享处理器非抢占，处理时长q_j=work_j×multiplier；报告仅在上传完成后可启动处理。
- 参考合同Task.upload表示固定独立延迟；上传扩展中同一数值表示活动传输工作量，实际经过时间包括队列和时隙等待。
- 快照只含已释放任务、实际车辆/处理状态、已承诺上传尾部与静态时隙参数。运行种子用于诊断记录，不参与决策逻辑；未来任务不在快照中。

## 精确路径释放

令A_i(t)为到t为止车辆i拥有的累计时隙长度：

    F_i(a,u) = inf{t >= a: B[A_i(t)-A_i(a)] >= u}.

从max(now, 已承诺上传尾部)开始，计入锁定采集尚未产生的包，然后对路径依次递推：

    R_jk = F_i(max(c_jk, R_j(k−1)), upload_jk).

实现的finish_time先消耗当前自有窗口余量、跳过整周期、落到最后部分窗口，O(1)预测完成时刻，不构造分段列表。执行器的transmit独立逐段服务；审计器通过累计容量闭式反算。三种实现以保守数值容差核对。

每车释放只依赖自己的锁定状态、上传尾部和路径，因此路径主问题使用实际合同的常数释放时间。释放下界冲突割作用于这些实际释放，既不使用借用上界代替物理释放，也不重排在传队列。N=1时链路连续可用，FIFO仍可能积压。

默认8车、0.2工作量的包在约1.6分钟内完成，小于最短后续采集2分钟；主矩阵主要检验时隙等待。已打开开发流的0.8工作量诊断单独检验FIFO积压，不作为额外独立确认。

## 结构因素与规模

八个b/c/u组合从同一seed的主工况变换。b=1把release向前归并到5分钟边界，deadline平移相同量，保留任务数量和每任务松弛；c=1按service+1.5×work排序重分同一个价值多重集；u=1启用TDMA/FIFO。位置、服务、工作和能力边际不变。组合相关，统计独立单位仍是seed。

16/32车检查使用参考固定延迟合同：到达率乘N/8，处理时长乘8/N，保持每车到达和名义处理负荷。区域不变也会改变空间车辆密度；不能从高完成率推出达到静态最优。每规模四条流，未增加网络模型规模结论。

## 评价和核验

主指标是全部释放价值中按时完成处理的价值比例；辅助指标包括无权重任务完成比例、未采集损失、下游损失、无效采集、事件时延与整集计算。完成/下游/未采集价值分区守恒。

逐条审计生成流指纹、公开可见性、路线及实际启动、车辆/处理占用、上传工作、FIFO顺序、时隙归属、全局分段互斥和完整排空。持平门控另外从物理日志重建位置及队首锁定，并核查留存、资源和一分钟余量。本次精简不附带原始记录或紧凑统计；审计函数可核查重新生成的执行记录。
